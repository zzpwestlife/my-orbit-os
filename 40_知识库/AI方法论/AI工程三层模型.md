# AI 工程三层模型

## 定义

AI 开发中三个递进的工程概念，构成包含关系：

```
Harness Engineering（驾驭工程）
  └─ Context Engineering（上下文工程）
       └─ Prompt Engineering（提示词工程）
```

> **核心公式：Agent = 大模型 + Harness Engineering**

## 三层详解

### 第一层：提示词工程（Prompt Engineering）

- **解决问题**：大模型无引导乱说话
- **定义**：有意识地设计和调整输入文本，让模型稳定输出期望的内容和格式
- **构成**：角色设定、背景、历史对话、参考文档、输出格式限制
- **原则**：提示词越长越细，回答越准

### 第二层：上下文工程（Context Engineering）

- **解决问题**：上下文窗口限制 + 上下文腐化
- **定义**：动态管理大模型上下文的技术（提示词工程是其子集）
- **上下文腐化**：上下文窗口满载后压缩/丢弃信息，导致模型"记不住"、前后不一致

**三步骤核心流程：**

| 步骤 | 说明 |
|------|------|
| **召回** | 从外部新闻、聊天记录、代码环境、运行报错等中找出最相关内容（涉及 RAG 等技术） |
| **压缩** | 将信息变小（摘要、过滤），减少 token 占用 |
| **组装** | 按特定结构和顺序组织信息（越靠后越受模型关注） |

### 第三层：Harness Engineering（驾驭工程）

- **解决问题**：长循环中 Agent 目标约束被冲淡、跑偏、死循环
- **定义**：包裹大模型的工程外壳，由四层能力组成

**四层架构：**

| 层 | 功能 | 实现方式 |
|----|------|----------|
| **编排层** | 全局规划，任务拆解与管控 | 子任务分解，明确执行标准 |
| **执行层** | 操作外部工具 | Bash 沙箱、文件系统、MCP |
| **反馈层** | 结果校验与自动修复 | 测试输出 + 报错 → 下一轮上下文 |
| **记忆层** | 保持核心信息稳定 | 规则文件（CLAUDE.md）自动注入 |

## 关键洞见

- **大模型越强，外壳可越薄，但必须有**
- 以 Claude Code 为例：原生支持四层能力，最轻量的落地是写好 `CLAUDE.md`
- 程序员工作重心转移：从写代码 → 定义规则和 Skills
