# AI 时代过渡技术考古

## 核心观点

> 只要你学得慢，就可以不用学。

凡是模型能力扩张路径上的技术生态位，迟早会被模型本身吞噬。选择有生命力的技术方向、培养判断技术发展前景的能力，比快速学会新技术更重要。

## 十大过渡性技术

### 1. Prompt Engineering → 从"职业"降为基础技能
模型意图识别能力增强 → 不再需要精雕细琢的咒语 → PE 沦为"吃饭喝水"级基础能力

### 2. SFT 监督微调 → 从核心方法降为基础课
依赖高质量标注数据（成本高昂）+ 缺少可解释性评估体系 → RLVR/GRPO/DAPO 等新方法上位

### 3. RAG → 从"标配"降为"选配"
上下文窗口扩大到百万级 → 模型本身能"记住"更多 → 外挂知识库的必要性下降

### 4. 多智能体框架 → 用鱼缸养鲸鱼
LangChain/CrewAI 等用上时代做 APP 的思维框定 AI → 进入门槛太低，差异化太小 → 单模型就能解决大部分需求

### 5. 低代码 Workflow → 确定性与不确定性的死结
Workflow 追求确定性 vs AI 输出天然不确定性 → 调试困难 → 被更智能的原生应用取代

### 6. MCP → 太"重"的万能接口
增加了一层语义与工具匹配层 → Agent Skills 的渐进式披露更轻量 → 复杂度超过问题本身

### 7. A2A 协议 → 超前的无需求创新
假设多个独立自主智能体需要"握手协商" → 实际场景单模型就够 → 需求未被验证就急于定义标准

### 8. GraphRAG → 画给外行看的饼
RAG + 知识图谱 → 复杂度翻倍但精度未等比提升 → 模型理解能力增强后性价比更低

### 9. 模型蒸馏 → 有门槛没普适
技术门槛高 + 市场空间有限 → 算力和模型效率跟上后"不得已"消失

### 10. OpenClaw → 验证了需求但产品太糙
安全性/成本稳定性/交互门槛三大问题 → 点燃赛道 ≠ 跑赢赛道

## 什么值得学？

学那些**"模型迭代杀不死"**的能力：

1. **管理 AI 的能力**：定义问题、拆解任务、大规模调度 AI 协同
2. **数据思维**：判断何时该信/该疑模型，建立评估体系
3. **垂直领域知识**：行业 know-how 是不可替代的核心资产
4. **安全思维**：控制 AI 不跑偏，或跑偏时及时发现纠正
