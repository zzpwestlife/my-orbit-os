# AI 时代的代码审查变革

## 核心论点

人类编写的代码在 2025 年已经消亡，代码审查将在 2026 年消亡。随着 AI 生成代码的规模和速度指数级增长，传统的人工代码审查模式已经无法适应新的工作流程。

> **新规则：**
> - 代码**不应该**由人类编写
> - 代码**不应该**由人类审查

## 问题：代码审查已经跟不上了

### 传统代码审查的困境

即使在人类以人类速度编写代码时，代码审查就已经跟不上了：
- PR 积压数天
- 橡皮图章式批准
- 审查者只能粗略浏览 500 行的 diff

代码审查从来不是完美的质量门：
- 直到 2012-2014 年才普及
- 即使有审查，代码仍然会出问题
- 我们已经学会构建能处理失败的系统（特性开关、灰度发布、即时回滚）

### AI 时代的新挑战

根据超过 10,000 名开发者、1,255 个团队的数据：
- 高 AI 采用率的团队完成任务数增加 **21%**
- 合并的 PR 数量增加 **98%**
- 但 PR 审查时间增加 **91%**

两个指数级增长：
1. **变更数量**的增长
2. **变更规模**的增长

开发者反馈：审查 AI 生成的代码比审查同事写的代码需要更多精力。

**结论：我们无法通过人工代码审查赢得这场战斗。**

## 解决方案：从审查代码到审查意图

### 1. 检查点上移

人类检查点需要从"代码实现"上移到"需求定义"：

**传统模式**：
```
需求 → 编码 → 代码审查 → 部署
```

**新模式**：
```
规格审查 → AI 编码 → 自动验证 → 部署
```

### 2. [[规格驱动开发]]（Spec-Driven Development）

在这个新范式中：
- **规格成为真理之源**
- **代码成为规格的产物**
- 你不需要审查代码，你审查步骤、验证规则、契约

人类的价值判断从"你写对了吗？"转向"我们在用正确的约束解决正确的问题吗？"

最有价值的人类判断是在第一行代码生成**之前**，而不是之后。

## 构建信任的层次

### 核心原则：瑞士奶酪模型

信任是分层的。采用 [[瑞士奶酪模型]]：没有单一门控能捕获所有问题，你需要堆叠不完美的过滤器，直到漏洞不再对齐。

### Layer 1: 比较多个选项

不要让一个 Agent 做对，而是让三个 Agent 用不同方式尝试，选择最佳结果。

选择标准：
- 通过最多验证步骤的
- 产生最小 diff 的
- 不引入新依赖的

### Layer 2: 确定性护栏

必须有确定性的方式验证工作：
- 测试
- 类型检查
- [[契约验证]]

护栏可以分层定义：
1. **编码规范** - 自定义 linter
2. **组织级不变量** - 不可协商的规则（如：禁止硬编码凭证）
3. **领域契约** - 特定于框架或服务（如：支付领域所有金额使用 Money 类型）
4. **验收标准** - 特定于任务

**关键**：验证步骤必须在代码编写**之前**定义，而不是事后发明。

### Layer 3: 人类定义验收标准

这是 [[行为驱动开发]]（BDD）重新变得相关的地方。

**传统问题**：写规格感觉像额外工作，因为你还要写代码。

**AI 时代**：规格不是额外工作，它是主要产物。

工作流程：
```gherkin
Given 用户已登录
When 用户点击"删除账户"
Then 系统显示确认对话框
And 对话框包含警告文本
```

Agent 实现 → BDD 框架验证 → 你无需阅读实现（除非失败）

人类做擅长的事：定义"正确"的含义，编码业务逻辑和边界情况，思考可能出错的地方。

### Layer 4: 权限系统作为架构

权限应该尽可能窄，同时仍让 Agent 能做有用的工作。

**示例**：
- 修复 `utils/dates.py` 中的 bug → 文件系统访问限制为该文件和测试文件
- 不是整个代码库，不是 `src/` 和 `tests/`，只是相关文件

**升级触发器**：
某些模式应自动标记人工审查：
- 触碰认证逻辑
- 修改数据库 schema
- 添加新依赖

### Layer 5: 对抗性验证

职责分离：一个 Agent 做工作，另一个验证。它们不信任彼此。

**架构强制**：
- 编码 Agent 不知道验证 Agent 会检查什么
- 验证 Agent 无法修改代码让自己的工作更轻松
- 它们在设计上是对抗的

**进一步**：第三个 Agent 尝试破坏第一个 Agent 构建的东西，专门针对边界情况和失败模式。红队、蓝队 - 但自动化并在每次变更时运行。

## 未来：快速发布，全面观测，更快回滚

### "好代码"的定义正在改变

对于 Agent 生成、Agent 阅读的代码：
- "好代码"的标准将更加标准化
- 新代码库需要更少的指导
- 默认值将更加一致

### 新的工作流程

**未来**：快速发布，观测一切，更快回滚

**不是**：缓慢审查，仍然遗漏 bug，在生产环境调试

### 核心转变

我们无法在阅读速度上超越机器。我们需要在思考上超越它们 - 在上游，在决策真正重要的地方。

**最终问题**：如果 Agent 能很好地处理代码，我们能否阅读它还重要吗？
