# Harness Engineering 完整指南

## 核心定义

**Harness = 除了 LLM 本身之外，让 Agent 真正能干活的一切基础设施。**

隐喻："马与缰绳"——为强大但方向不定的"野马"（AI Agent）套上"缰绳"（Harness），通过约束、引导并纠正其行为，确保沿预设轨道稳定前行。

> AI Agent = SOTA 模型（野马）+ Harness（驾驭系统）= 千里马

## R.E.S.T 模型

Agent 从"有趣的玩具"变为"可靠的工具"需满足四个核心目标：

| 维度 | 关键要求 |
|------|---------|
| **Reliability（可靠性）** | 失败可恢复、操作幂等性、行为一致性 |
| **Efficiency（效率）** | Token 预算控制、低延迟、高吞吐 |
| **Security（安全性）** | 最小权限、沙盒执行、输入/输出过滤 |
| **Traceability（可观测性）** | 全链路追踪、决策可解释、状态可审计 |

## Harness 作为 REPL 容器

- **Read**：上下文管理器将外部世界"翻译"成结构化 Prompt
- **Eval**：调用拦截器捕获 Function Calling 意图，路由到工具执行器
- **Print**：反馈汇编器将执行结果组装为"观测结果"，重新注入上下文
- **Loop**：持续循环直到达到目标或触发终止条件

## 六大设计原则

1. **为失败而设计**：异常是常态，所有组件具备容错和优雅降级
2. **契约优先**：所有交互由机器可读的契约（Schema/API/Event）定义
3. **默认安全**：最小权限、零信任、纵深防御
4. **决策与执行分离**：规划与执行在逻辑和物理上解耦
5. **万物皆可度量**：每个行为、决策、资源消耗都可度量
6. **数据驱动进化**：每次运行都是学习机会，建立数据闭环

## 系统架构：控制平面 + 数据平面

- **控制平面**：任务调度、资源配额、行为规划、策略与权限
- **数据平面**：Agent 运行实例、状态存储、记忆存储、沙盒执行环境

## 关键工程位点

### 上下文管理
- **规约规则**：Token 预算紧张时决定保留/牺牲哪些信息
- **注入边界**：外部信息在 Prompt 中的最佳注入位置
- **Token 转化流水线**：信息源收集 → 相关性排序 → 压缩摘要 → 预算分配 → 模板组装

### 沙盒执行
- Level 1：进程级隔离（chroot/namespaces）
- Level 2：容器级隔离（Docker）← 推荐默认
- Level 3：轻量级虚拟机（Firecracker）← 不可信代码
- Level 4：完整虚拟机（KVM/QEMU）

### 策略门控
权限检查（RBAC/ABAC）、敏感数据过滤、指令注入防御、审计日志

## 核心原则

> LLM 必须被严格视为**无状态的计算单元（CPU）**，所有跨轮次状态存储在 Harness 控制的外部状态管理器中。
