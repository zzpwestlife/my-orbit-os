# Autoresearch 迭代方法论实践

对 Karpathy 开源的 autoresearch 项目背后迭代方法论的通俗拆解与实践应用。

## 核心观点

**autoresearch 不是一个 ML 工具，而是一个通用的迭代框架。任何你能打分的东西，都能套进去自动优化。**

## 核心逻辑

**改一个东西 -> 打分 -> 分高了保留，分低了回滚 -> 再改下一个。**

Karpathy 用这个循环优化 AI 模型训练代码：每次改一点参数或结构，训练 5 分钟，看验证损失有没有降，降了就留，没降就回滚。一晚上能跑 100 次实验，无需人工干预。

## 关键洞察

### 1. 通用迁移能力
把"训练代码"替换成任何可量化的东西：
- **广告文案** -> 改标题，测点击率
- **冷启动邮件** -> 改开场白，测回复率
- **产品定价策略** -> 改价格锚点，测转化
- **AI 生成内容** -> 改 prompt 规则，打分

### 2. Checklist 设计原则
- **使用 Yes/No 而非 1-10 分**：打分有主观性，同一篇文章今天 7 分明天可能 6 分，但"第一句话有没有数字"是客观事实
- **标准越客观，迭代越稳定**
- **控制在 3-6 个问题**：太少覆盖不够，太多容易失焦
- 问题需具体可验证，例如：
  1. 第一句话有没有具体数字或强反差？
  2. 有没有用日常比喻解释技术概念？
  3. 有没有具体可验证的数字（非空话）？
  4. 有没有出现套话？
  5. 结尾互动问句够不够具体？
  6. 字数在目标范围内？

### 3. 双层打分系统（社区实践）
- **第一层**：按规则逐条核查（Checklist，每条要么过要么不过）
- **第二层**：切换"读者视角"，放下所有规则，只凭感受打分
- 两层分数结合决定：直接通过 / 针对扣分项定向重写 / 整稿推倒重来

### 4. 实践数据验证
**小红书内容生成实验：**
- 第一轮（6 条标准）：有 Skill 100% vs 无 Skill 66.7%，差距 +33%
- 发现问题后增加 2 条规则（标签热度、金句独立成段）
- 第二轮（8 条标准）：有 Skill 100% vs 无 Skill 37.5%，差距 +62%
- Skill 学会了新规则，无 Skill 原地踏步

### 5. 框架的价值
- **没有框架思维**：看到 autoresearch 觉得"这是个 ML 工具，跟我没关系"
- **有框架思维**：脑子里自动映射出十个可套用的场景
- **限制你的不是工具，是你有没有把眼前这件事抽象成可复用的思路**

## 如何开始

不需要跑代码，不需要懂 ML。只需要：
1. 找到一件你重复在做、但结果时好时坏的事
2. 回答：什么样的结果算好？能不能拆成几个具体的是非题？
3. 能回答这个问题，就有了开始迭代的全部条件
4. 剩下的，交给 AI 去跑
